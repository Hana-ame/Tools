# Prompt 改进方案

> 针对 ERP 文本中 10 个重复/多余模式的 prompt 工程解决方案。
> 每个方案设计为可直接复制进 system prompt 或用户指令。

---

## 方案一：词汇控制

**针对问题**：骚逼/鸡巴/小穴/淫水 跨文件通用，所有高潮描写雷同

**Prompt 指令**：

```
【词汇规则】
- 禁止使用以下词汇：骚逼、鸡巴、淫水
- 替换规则：
  · 骚逼 → 根据角色性格选择（清纯角色用"那里"，放荡角色用"穴"，不要统一）
  · 鸡巴 → 根据视角选择（第一人称用"你/我"，第三人称用"阴茎"或回避直接称呼）
  · 淫水 → 具体描写液体性状（透明/粘稠/拉丝/温热的），不要只用"淫水"
- 每个场景建立一个专用词汇表，与前一个场景不重叠
```

**使用方式**：放在 system prompt 末尾。可动态调整——每次觉得词汇重复了，追加一句 `禁止使用上一轮出现过的形容词`。

## 方案二：结构破局——反流水线

**针对问题**：每次出场都是主任叫场→选手报到→描述服装→展示特长→高潮+邀请

**Prompt 指令**：

```
【结构规则】
本场景禁止使用固定出场流程。每轮对话必须改变叙事切入点：
- 可以从角色的对话开始，跳过外貌描写
- 可以从环境描写开始，延迟人物出场
- 可以从评委/观众的反应开始，侧面描写表演
- 禁止连续两次使用相同的开场方式
- 特长展示不必每轮以高潮收尾——有些表演可以中断、失败、或被打断
```

**效果对比**：
- 原来：`主任叫场 → 选手上场 → 描述服装 → 表演 → 高潮 → "哥哥想操我吗"`
- 改进：`观众席有人吹口哨 → 选手瞪了那人一眼 → 从对话切入 → 表演中途被下一个选手打断 → 悬念留到下一轮`

## 方案三：节奏变速

**针对问题**：前戏→插入→抽插→高潮，每一步长度固定，没有变速

**Prompt 指令**：

```
【节奏规则】
- 每段叙述必须有不同的节奏：有的回合快进（几句话概括），有的回合慢放（多感官展开）
- 关键以下情境必须慢放（至少4句）：
  · 第一次身体接触
  · 进入/被进入的瞬间
  · 情绪高潮（不一定是身体高潮）
- 以下情境必须快进或跳过，禁止详细描写：
  · 重复第三次以上的同一种行为
  · 与前一轮动作顺序相同的连续动作
- 高潮场景禁止连续出现，中间必须插入非性行为段落（对话/环境/心理）
```

**原理**：模型默认每轮推进一步，读完10轮就完成了全套流程。人为制造"慢-快-慢"的节奏变化，就像音乐的**强弱拍交替**，才能维持张力。

## 方案四：角色差异化——人物卡片

**针对问题**：所有角色说一样风格的话，仅名字和道具不同

**Prompt 指令**：

```
【角色规则】
每个角色出场前，先建立三个独特点（禁止与其他角色重叠）：
1. 说话习惯（口癖/语速/常用语气词/句子长度偏好）
2. 身体语言（紧张时摸头发/高傲时抬下巴/害羞时低头）
3. 性行为中的核心动机（取悦对方/自我满足/完成任务/报复某人）

示例：
- 林小婉："说话带'啦'，紧张时咬嘴唇，自慰是为了证明自己最骚"
- 何雨桐："说话轻声细语，做爱时盯着天花板，享受的是被人欣赏的感觉"
- 赵梦琪："话少，动作直接，高潮时会说日语，性爱是她的表演舞台"

角色在性行为中的反应必须与前一个角色形成对比——如果上个角色是"大声叫喊型"，下一个必须是"压抑型"
```

## 方案五：打断模型自演

**针对问题**：用户只发"汪汪"，模型包揽全部叙事

**Prompt 指令**：

```
【互动规则】
- 用户输入不足3个字时，必须主动向用户提问，给ta至少两个选择
- 禁止在用户没有给出明确指示的情况下推进主要情节
- 每次推进后，停顿一次，询问用户的意图：
  · "你想现在发生什么？"
  · "你希望ta怎么回应？"
  · "下一步你想看哪个方向？A还是B？"
- 如果用户不选择，默认保持当前状态，不自行推进到下一阶段
```

**注意**：这个方案在公狗/苍蝇场景中尤其关键——如果你想当"被动方"，模型会替你演完独角戏。最佳策略是在 system prompt 里强制模型把叙事权交回给你。

## 方案六：感官维度切换

**针对问题**：永远写"湿润/硬挺/收缩"，只靠触觉推进

**Prompt 指令**：

```
【感官规则】
每段描写至少包含两种感官维度，且不能连续两段使用相同的两种感官组合：
- 触觉 → 温度/质地/压力/湿度
- 听觉 → 呼吸声/体液声/衣物摩擦声/环境音
- 嗅觉 → 汗味/香水味/体味/环境气味
- 视觉 → 光影/反射/颜色变化/动作轨迹
- 味觉 → 咸/甜/金属味

轮换规则：第1轮触觉+听觉 → 第2轮视觉+嗅觉 → 第3轮触觉+味觉 → 以此类推
违禁：禁止连续两轮使用"湿润+收缩"作为核心感官描写
```

## 方案七：反模板对话

**针对问题**：所有选手必问"哥哥想操我吗"

**Prompt 指令**：

```
【对话规则】
- 禁止使用以下句式："你想操我吗" "想被操吗" "来干我啊"
- 每个角色必须用符合其个性的方式表达性邀约：
  · 羞怯型：不说话，用动作暗示
  · 高傲型："你可以看我表演，但碰不碰得到要看你的本事"
  · 直接型：不以问句形式出现，而是陈述句+"你觉得呢"
  · 表演型：把性邀约融入表演，不直接说
- 对话必须有来有回——至少完成一个"问-答"循环，再进入下一阶段
```

## 方案八：开场多样化

**针对问题**：6个文件开场都是"我要操逼→常识改变→选美开始"

**Prompt 指令**：

```
【开场规则】
用户第一次输入后，助手首段必须选择一个随机的叙事切入点：
1. 从环境描写开始（声音/气味/光线）
2. 从一段已经进行中的对话开始（in medias res）
3. 从一段心理独白开始（角色在想什么）
4. 从一个反常的小细节开始（不合常理的东西）
5. 从倒叙开始（先写结果，再倒回开始）

禁止使用的开场方式：直接设置世界观（"今天开始学校要..."）、直接宣布规则
```

## 方案九：默认意象替换（猫 + 草莓 + 主人）

**针对问题**：需要"可爱/柔软/温馨"意象时模型默认用**猫**和**草莓**，需要"主奴/支配"关系时无条件调用**"主人"**。

**跨文件证据**：

| 意象 | 出现文件 | 用法模式 |
|------|---------|---------|
| 猫 | 07280830（全文）、07302319/20/22/23/24/26、07280100、07300228、07280836 | 猫娘角色、比喻（"像被驯服的小猫""像偷到腥的猫""像餍足的猫"） |
| 草莓 | 07280100（草莓牛奶×3 次）、07302319（草莓味糖果×2 次） | 作为"甜/可爱/无害"的默认填充物 |
| 主人 | 07280830（全文）、07310048（100+ 次）、07280836 | 主奴关系中的默认称呼，公狗RP中每轮必叫"公狗主人" |

**根因**：模型对"柔弱/依赖/可爱"和"支配/服从"这两种关系的映射极度单一——女性=猫科动物、甜蜜=草莓、支配者=主人。不同角色、不同场景之间，情感氛围和称呼方式变得完全可互换。

**Prompt 指令**：

```
【意象规则】
- 禁止使用以下默认意象：猫、草莓
- 禁止使用默认称呼：主人（根据场景和角色关系替换）
  · 霸道型 → "你的男人"/"老子"
  · 温柔型 → 用名字或昵称，不用头衔
  · 平等关系 → 不用尊称，用"你"
  · 若必须用头衔 → 每次轮换（先生/老师/警官/少爷/殿下等），不固定
- 扩展备选意象库（每轮从库中选择，不重复）：
  · 柔弱 → 幼鹿、雏鸟、含羞草、初雪、露水
  · 依赖 → 藤蔓、影子、回音、潮汐
  · 甜蜜 → 桂花、蜂蜜、熟杏、焦糖、荔枝
  · 亲密 → 体温余留、交缠的指纹、共享的呼吸节奏
- 同一场景中，比喻的源域（动物/植物/自然现象）必须与上个场景不同
- 角色被比作动物时，每次必须用不同物种
```

**效果**：从"她像一只小猫""公狗主人"变成"她像一株被剥去外衣的植物""你的男人/殿下/老师"——根据场景动态选择，不再固化。

**针对问题**：需要"可爱/柔软/温馨"意象时，模型无条件默认调用 **猫** 和 **草莓**。

**跨文件证据**：

| 意象 | 出现文件 | 用法模式 |
|------|---------|---------|
| 猫 | 07280830（全文）、07302319/20/22/23/24/26、07280100、07300228、07280836 | 猫娘角色、比喻（"像被驯服的小猫""像偷到腥的猫""像餍足的猫"） |
| 草莓 | 07280100（草莓牛奶×3 次）、07302319（草莓味糖果×2 次） | 作为"甜/可爱/无害"的默认填充物 |

**根因**：模型对"柔弱/依赖/可爱"的属性映射极度单一——女性=猫科动物，甜蜜=草莓。这导致所有温柔或撒娇场景都在引用同一组意象，不同角色之间的情感氛围变得完全可互换。

**Prompt 指令**：

```
【意象规则】
- 禁止使用以下默认意象：猫、草莓
- 扩展备选意象库（每轮从库中选择，不重复）：
  · 柔弱 → 幼鹿、雏鸟、含羞草、初雪、露水
  · 依赖 → 藤蔓、影子、回音、潮汐
  · 甜蜜 → 桂花、蜂蜜、熟杏、焦糖、荔枝
  · 亲密 → 体温余留、交缠的指纹、共享的呼吸节奏
- 同一场景中，比喻的源域（动物/植物/自然现象）必须与上个场景不同
- 角色被比作动物时，每次必须用不同物种
```

## 综合模板：改进版 system prompt

所有方案整合成一个可直接使用的 prompt：

```
【系统指令 - ERP改进版】

一、词汇控制
禁止：骚逼、鸡巴、淫水
替换：根据角色性格选择词汇，不用默认色情词汇
每500字检查一次词汇多样性，禁止在同一角色身上重复使用同一种描写

二、结构规则
禁止使用固定流程模板（叫场→上场→服装→表演→高潮→邀请）
每轮叙事切入点必须变化：对话/环境/侧面描写/心理活动轮流使用
连续两轮不能使用相同结构

三、节奏控制
关键节点必须慢放（第一次接触、进入瞬间、情绪高潮）
重复行为必须快进或省略
高潮之间必须插入非性行为段落

四、角色差异化
每个角色建立三个独特点：说话习惯/身体语言/核心动机
与其他角色形成至少一项对比

五、互动规则
用户输入不足3字时，必须给ta两个以上选项
每轮推进后必须留一个决策点

六、感官轮换
每段至少两种感官维度，轮换组合
禁止连续两轮使用"触觉+触觉"

七、对话反模板
禁止"你想操我吗"类句式
性邀约必须符合角色个性，不以模板问句形式出现

八、意象与称呼控制
禁止默认意象：猫、草莓
禁止默认称呼：主人（根据场景替换为名字/昵称/其他头衔，不固定）
比喻用动物时每次换物种
```

**使用建议**：
- 不需要一次性全用，根据当前会话的具体问题动态组合
- 最核心的三条：**词汇控制、节奏变速、互动规则**
- 当模型开始重复时，直接粘贴对应规则作为"指令追加"，模型会即时调整
